## 실제 핀 배정 (W2 확정, 코드 기준)

| 기능 | 핀 | 설정 | 근거 코드 |
|---|---|---|---|
| UART printf (USART2 TX) | **PA2** | AF7, 115200 8N1 | `Core/Src/usart.c` |
| UART printf (USART2 RX) | **PA3** | AF7 | `Core/Src/usart.c` |
| I2C1 SCL (MPU6050) | **PB8** | AF4, 100kHz | `Core/Src/i2c.c` |
| I2C1 SDA (MPU6050) | **PB9** | AF4, 100kHz | `Core/Src/i2c.c` |
| 유저 LED (LD2) | **PA5** | 출력 (푸시풀) | `Core/Src/gpio.c` |
| 유저 버튼 (B1) | **PC13** | 입력, 하강 에지 인터럽트 | `Core/Src/gpio.c` |

- PA2/PA3, PA5, PC13은 Nucleo 보드 배선(ST-LINK VCP, LD2, B1)으로 정해진 것.
- HAL 타임베이스는 **TIM10** (SysTick은 FreeRTOS 소유 — qna-core.md Q14).
- 마감시한 이벤트 타이머는 **TIM2** (내부 전용, 핀 없음) — W2 이벤트→액션 지연 측정용.
- HC-SR04용 타이머 인풋캡처 핀은 시나리오 확정(W3) 시 여기 추가.

### MPU6050 (GY-521) 배선

| GY-521 핀 | 연결 | 비고 |
|---|---|---|
| VCC | 3.3V | |

## 전원 — 단순화됨

모터가 없으므로 **Nucleo는 USB 전원만으로 충분**하다.

HC-SR04(채택 시)는 5V가 필요 — Nucleo 헤더의 5V 핀(USB VBUS 유래)에서 공급 가능한지
보드 실물로 확인, 안 되면 브레드보드 전원모듈(배럴잭 입력) 사용.

W5 "휴대용 데모" 스트레치 시 배터리/VIN 조합을 재검토 (지금은 보류 → 아카이브 §6).

## 배선 색상 규칙

| 색 | 용도 | 비고 |
|---|---|---|
| 검정 | GND | 예외 없이 전부. 다른 용도로 쓰지 않는다 |
| 노랑 | 3.3V | Nucleo 3.3V 출력, GY-521 로직 전원 |
| 주황 | 5V | HC-SR04 VCC (채택 시) |
| 파랑 | I2C SDA | |
| 초록 | I2C SCL | |
| 흰색/회색 | HC-SR04 Trig/Echo 신호 | |

**원칙**: 검정=GND는 절대 다른 용도로 재사용하지 않는다. 색이 부족하면 GND/전원부터
확보하고, 신호선은 라벨 테이프로 구분. (색은 전기적 의미가 아니라 참고용 라벨링 —
안 지켜도 동작엔 문제없음)

## 미결 항목 — 없음 (2026-08-08 종결)

- [x] ~~HC-SR04 Echo(5V) → STM32 GPIO(3.3V) 분압 저항값~~ — **해당 없음.**
      W3에서 시나리오를 **IMU 예지보전**으로 확정했고(PLAN.md §5 · system-design.md §4),
      그 시나리오는 HC-SR04를 안 쓴다. 분압 저항 미확보가 리스크였는데, 시나리오 선택으로
      리스크 자체가 사라졌다. HC-SR04 2개는 스트레치(재실감지)로 남는다.
- [x] ~~HC-SR04 VCC 5V 공급원~~ — 위와 동일 조건, 해당 없음.

**핀 배정은 W3에서 바뀌지 않았다.** 추가된 것(추론 태스크, float32 대조군 커널,
MPU6050 레인지·DLPF 설정)은 전부 소프트웨어이고, 새 주변장치나 핀을 쓰지 않는다.
MPU6050의 `INT` 핀(DRDY)은 여전히 미연결 — 폴링으로 충분하고, 연결하려면 CubeMX에서
EXTI를 새로 잡아야 한다([references.md §3](references.md)의 `SMPLRT_DIV` 논의 참조).
