# 부품 가이드 — 생김새 · 용도 · 활용

> PLAN.md §1 BOM에 대응하는 "실물 편람". 박스 열었을 때 뭐가 뭔지 식별하고,
> W2 브링업에서 어디에 꽂을지 판단하기 위한 문서.
> 개념(I2C/PWM/인풋캡처/전원)은 [sensor-actuator-basics.md](sensor-actuator-basics.md) 참조.
>
> ⚠️ 이 문서의 핀 이름은 **모듈 실크스크린 기준의 일반적인 표기**다.
> 실제 배선 전에 보드에 인쇄된 글자를 눈으로 확인할 것. 벤더마다 순서가 다른 모듈이 있다.

> **변경 이력 (2026-07-23)**: 프로젝트 A가 자율주행 카 → 이상거동 감지+근접경고(A+C)로
> 전환됨(PLAN.md §0). 모터/섀시/라인센서 섹션은 삭제하지 않고 **[보류]**로 표시만 해뒀다 —
> 나중에 로봇 사이드 프로젝트로 재개할 때 그대로 참고 가능. 아래 표로 한눈에 확인.

## 부품별 사용 여부 (2026-07-23 기준)

| 부품 | 상태 | 새 역할 |

| GY-521 (MPU-6050) | 사용 | 이상거동 분류의 입력원 (그대로) |
| HC-SR04 ×2 | 사용 | 근접경고(주차보조) |

## 0. 한눈에 보는 역할 분담

```
        [18650 ×2 = 7.4V]
               |
        +------+---------------------------+
        |                                  |
   [L298N 모터드라이버]                 (L298N 5V 출력)
        |         ^                        |
   [기어모터 ×2]  | PWM/방향 4~6핀          |
                  |                    [브레드보드 전원레일 5V]
             [Nucleo-F411RE] ------------- 3.3V ---+
                  |  |  |                          |
             I2C  |  |  +-- GPIO ×3 --- [TCRT5000 ×3]  (라인 감지)
                  |  +----- 타이머 IC -- [HC-SR04 ×2]  (거리)
                  +-------- I2C -------- [GY-521/MPU6050] (IMU → AI 입력)
                  |
                 USB(ST-LINK) → PC: 디버깅 + UART printf
```

핵심: **모터 전원(7.4V)과 로직 전원(3.3V)은 분리하되 GND는 반드시 하나로 묶는다.**

## 1. Nucleo-F411RE — 두뇌

**생김새**: 가로로 긴 하늘색(민트) PCB. 위쪽 1/3이 잘린 선(perforation)으로 구분되는데
그 부분이 **ST-LINK 디버거**(고정 부품, 잘라내지 말 것). 아래쪽이 실제 STM32F411RE.
양옆에 검은 암(female) 헤더 2열(모포 헤더, ST Zio) + 안쪽에 Arduino Uno 호환 헤더.
파란 버튼(B1, 사용자 버튼), 검은 버튼(B2, RESET), LED 3개(LD1 통신/LD2 사용자/LD3 전원),
Mini-USB 아닌 **Mini-B USB 커넥터** 1개.

**용도**: STM32F411RE = Cortex-M4F @ 100MHz, Flash 512KB, SRAM 128KB, FPU 있음.
이 프로젝트의 모든 것(FreeRTOS, 센서 폴링, 모터 PWM, int8 추론)이 여기서 돈다.

**활용 포인트**
- USB 하나로 **전원 + 플래싱 + 디버깅 + 가상 COM 포트(UART printf)** 가 전부 해결된다.
  W1 DoD의 "UART printf"가 여기에 걸려 있음 → `stm32-basics.md §7` 리타겟 코드.
- 보드에서 나오는 GPIO는 **3.3V 로직**. 5V 신호를 직접 물리면 핀이 죽을 수 있다
  (HC-SR04 Echo가 대표적인 함정 → §5).
- 점퍼 설정(JP5 등)으로 USB 전원 / 외부 전원(VIN)을 고른다. 주행 시에는 배터리로
  돌려야 하므로 W2 화요일 "전원 계통 확정"에서 **어느 점퍼를 어떻게 둘지 데이터시트
  (UM1724 Nucleo-64 user manual)를 보고 확정**해야 한다. 지금 단정하지 않는다.
- DWT 사이클 카운터(W4의 핵심 계측기)가 Cortex-M4 코어에 내장 → 별도 부품 불필요.

## 2. [보류] 2WD 자동차 키트 (기어모터 + 바퀴 + 섀시)

> 현재 계획(A+C)에서는 사용하지 않는다. 로봇 사이드 프로젝트 재개 시 참고용으로 보존.

**생김새**: 투명 아크릴 또는 알루미늄 판 1~2장(구멍 다수), 노란 플라스틱 기어박스에
DC 모터가 붙은 **TT 기어모터** 2개, 검은 고무 타이어 2개, 앞쪽에 굴러가는
**캐스터(볼 캐스터/유니버설 휠)** 1개, 나사·너트·구리 스페이서 한 봉지.

**용도**: 차체. 2WD = 뒤(또는 앞) 두 바퀴만 구동, 나머지는 자유롭게 구르는 캐스터.
좌우 바퀴 속도차로 조향한다(differential drive) → **별도 조향 서보가 필요 없다.**

**활용 포인트**
- TT 모터는 보통 3~6V 정격. 7.4V를 그대로 100% 듀티로 물리면 수명이 짧아진다.
  → PWM 듀티 상한을 코드에서 걸어두는 편이 안전 (예: 70~80%).
- 모터 단자에 리드선이 안 붙어 있는 키트가 많다 → **납땜 필요**.
  납땜 후 케이블을 섀시에 고정(케이블타이)하지 않으면 주행 중 끊어진다.
- 좌우 모터의 회전 방향이 물리적으로 반대(마주보게 장착)이므로,
  "둘 다 전진" = 드라이버 입력은 서로 반대 조합이 된다. 배선 극성은 뒤집어 꽂아
  맞추면 되고, 이건 W2 월요일에 실험으로 확정할 사항.
- **라인 센서 장착 위치가 주행 성능을 좌우한다**: 앞쪽 최대한 낮게, 바닥에서 3~10mm.
  섀시 앞단에 스페이서로 매다는 형태가 된다.

## 3. [보류] L298N 모터 드라이버 (PP-A063)

> 현재 계획(A+C)에서는 사용하지 않는다. 로봇 사이드 프로젝트 재개 시 참고용으로 보존.

**생김새**: 명함 절반 크기 PCB (**색은 벤더마다 초록/빨강/파랑/검정 — 회로와 무관**).
가운데 **커다란 알루미늄 방열판**이 박혀 있고 그 아래 검은 L298N 칩.
양옆에 나사로 조이는 파란 **터미널 블록** 3개
(OUT1/OUT2, OUT3/OUT4, +12V/GND/+5V), 옆에 점퍼 캡 3개
(ENA, ENB, 5V-EN)와 IN1~IN4 핀헤더.

**실물 식별 체크 (색이 달라도 이걸로 판별)**
1. 방열판 아래 칩 각인이 `L298N` 인가 — 방열판 없는 손톱 크기면 다른 드라이버
   (L9110S / TB6612FNG / DRV8833 등)일 수 있다
2. 파란 터미널 블록 3개, 점퍼 캡 3개(ENA/ENB/5V-EN) 존재 여부
3. ⚠️ **터미널 순서가 벤더마다 뒤집혀 있다.** `+12V/GND/+5V`가 아니라
   `+5V/GND/+12V`로 인쇄된 보드도 있음 → **사진 기억이 아니라 실크스크린 글자를 읽고 꽂을 것**

**용도**: MCU의 약한 3.3V 신호로 **모터의 큰 전류를 스위칭**하는 H-브리지 2채널.
방향(정/역/정지) + PWM 속도 제어.

**활용 포인트**
- 배선 개념: `IN1/IN2` → OUT1/OUT2(모터 A) 방향, `ENA` → 속도 PWM. B채널도 동일.
  ENA/ENB에 꽂힌 **점퍼 캡을 뽑아야** 그 핀에 PWM을 넣을 수 있다 (꽂혀 있으면 항상 최대속).
- `5V-EN` 점퍼가 꽂혀 있으면 온보드 7805 레귤레이터가 동작해 **+5V 핀이 5V를 출력**한다
  (입력이 7~12V일 때만). 이 5V로 브레드보드 로직 레일을 먹일 수 있다.
  ⚠️ 반대로 외부에서 5V를 넣어줄 거면 이 점퍼는 빼야 한다. **동시에 하면 안 된다.**
- L298N은 구식 바이폴라 소자라 **전압 강하가 1.5~2V 정도** 있다. 7.4V 넣어도
  모터엔 5V대가 걸린다 — TT 모터 정격 관점에서는 오히려 다행.
- 방열판이 뜨거워지는 건 정상. 손 델 정도면 듀티/부하를 의심.
- **가장 흔한 사고: 모터 돌릴 때 MCU 리셋** → 모터 역기전력/전압 강하.
  대응은 공통 GND 확인, 로직 전원 분리, 굵은 전선. (PLAN.md W2 삽질 메모와 동일)

## 4. GY-521 (MPU-6050) — 이 프로젝트 AI의 입력원

**생김새**: 손톱 두 개 크기의 파란(또는 보라) 소형 PCB. 가운데 4mm 각짜리 검은 QFN 칩,
가장자리에 8핀 헤더(VCC, GND, SCL, SDA, XDA, XCL, AD0, INT). 구매 시 핀헤더 납땜 옵션 선택함.

**용도**: 3축 가속도계 + 3축 자이로스코프 (6축 IMU). I2C로 통신.
**이상 동작/진동 분류(또는 예지보전) 모델의 유일한 입력 데이터가 여기서 나온다.**
즉 이 프로젝트에서 가장 중요한 센서.

**활용 포인트**
- I2C 주소: `AD0` 핀이 GND면 `0x68`, VCC면 `0x69`. 모듈에 보통 풀다운이 있어 기본 0x68.
  (HAL의 `HAL_I2C_Mem_Read`는 7비트 주소를 << 1 해서 넘겨야 함 — 첫 삽질 포인트)
- `WHO_AM_I` 레지스터를 읽어 고정값이 나오는지가 브링업 1단계 (W2 수요일).
  구체적 레지스터 번호/기대값은 MPU-6000/6050 Register Map 문서로 확인할 것 — 여기선 단정 안 함.
- 전원 투입 후 **슬립 모드로 시작**하므로 전원관리 레지스터를 깨우지 않으면
  데이터가 계속 0이 나온다. "배선은 맞는데 값이 안 변한다"의 90%가 이것.
- 모듈에 3.3V 레귤레이터와 I2C 풀업이 이미 올라가 있는 버전이 많다(GY-521 계열).
  VCC를 5V로 줄지 3.3V로 줄지는 보드 실물 확인 후 결정.
- **장착 방향을 고정하고 문서화할 것.** 학습 데이터의 축 방향과 추론 시 축 방향이
  다르면 모델이 통째로 무의미해진다. 측정 대상(또는 고정판/브레드보드)에 단단히(양면테이프+케이블타이) 고정,
  진동으로 흔들리면 노이즈가 라벨보다 커진다.
- 샘플링 100Hz가 W2 DoD. 이 스트림이 그대로 W3 데이터셋이 된다.

## 5. HC-SR04 초음파 센서 ×2

**생김새**: 파란 PCB에 **은색 원통 두 개**(눈처럼 생긴 트랜스듀서)가 나란히 붙어 있고
그 사이에 크리스털/칩. 뒷면 4핀: VCC, Trig, Echo, GND.

**용도**: 거리 측정(약 2cm~4m). 이 프로젝트에서는 **재실/움직임 감지(스마트홈 엣지 노드 시나리오)
또는 마감시한 이벤트의 실측 소스**로 쓸 수 있다 — 기본은 타이머 ISR 이벤트이고 HC-SR04는 스트레치/대안(PLAN.md §0·§1).

**활용 포인트**
- 동작: Trig에 10µs HIGH 펄스 → 센서가 8회 버스트 송신 → Echo 핀이 왕복시간만큼 HIGH.
  그 **HIGH 폭을 타이머 인풋캡처로 재는 것**이 W2 목요일 과제.
- ⚠️ **Echo 출력은 5V**다. 3.3V인 STM32 핀에 직결하면 안 된다.
  분압 저항(예: 1kΩ + 2kΩ) 또는 레벨 시프터 필요. 이건 부품 목록에 저항이 없으므로
  **W2 전에 저항을 확보하거나 대안을 정해야 한다** (미해결 항목).
- 측정 주기는 60ms 이상 확보. 너무 빨리 쏘면 이전 반향이 섞여 값이 튄다.
- 부드러운 천/비스듬한 면은 반사가 안 돌아와 뻥 뚫린 값이 나온다. 중앙값 필터 권장.

## 6. [보류] TCRT5000 모듈 ×3 (LM393 + 가변저항)

> 현재 계획(A+C)에서는 사용하지 않는다. 로봇 사이드 프로젝트 재개 시 참고용으로 보존.

**생김새**: 작은 PCB. 앞쪽에 **검-파랑 2색 사각 소자**(왼쪽 적외선 LED, 오른쪽 포토트랜지스터)가
아래를 향해 붙어 있고, 뒤에 파란 **가변저항(십자 드라이버로 돌리는 것)**, LM393 비교기 칩,
LED 2개(전원 표시 + 출력 표시). 핀: VCC, GND, DO(디지털 출력), 보통 AO(아날로그)도 있음.

**용도**: **라인 트레이싱의 눈.** 적외선을 바닥에 쏘고 반사량을 본다.
흰 바닥 = 반사 많음, 검은 절연테이프 = 반사 적음 → 라인 위/밖 판별.

**활용 포인트**
- 3개를 앞쪽에 **좌 / 중 / 우** 배치. 조합으로 조향 결정:
  `중앙만 검정` → 직진, `좌측 검정` → 좌회전, `전부 검정` → 교차로/정지선, `전부 흰색` → 라인 이탈.
- **가변저항 캘리브레이션이 전부다.** 실제 트랙(다이소 검은 절연테이프 + 실제 바닥 재질,
  실제 조명)에서 드라이버로 돌리며 출력 LED가 라인 경계에서 딱 바뀌게 맞춘다.
  이걸 대충 하면 이후 며칠을 코드에서 헤맨다.
- 감지 거리가 매우 짧다(수 mm~1cm대). 바닥에 최대한 가깝게, 그러나 긁히지 않게.
- DO만 쓰면 GPIO 입력 3개로 끝난다(W2 목요일 계획). AO를 ADC로 읽으면 라인 중심
  오차를 연속값으로 얻어 PID가 가능해지는데, **W2 범위 밖 — 시간 남으면**.
- 주변광(형광등/햇빛)에 영향받는다. 데이터 수집(W3)과 데모를 같은 조명에서.

## 7. 전원 계통: 18650 ×2 + 홀더 + 충전기

**18650 배터리 (2600mAh, 보호회로 내장, KC인증) ×2**
- 생김새: AA보다 굵고 긴 은색/검은색 원통(지름 18mm, 길이 65mm). 보호회로 내장형은
  70mm에 가깝고 (+)극 쪽이 살짝 튀어나와 있다.
- 셀당 공칭 3.7V(만충 4.2V, 방전 종지 ~3.0V). 2직렬 = **공칭 7.4V**.

**18650 홀더 2구 / 2선 (오픈형, 직렬)**
- 생김새: 검은 플라스틱 트레이 2칸, 빨강/검정 리드선 2가닥. **뚜껑 없음(오픈형)**.
- ⚠️ PLAN.md 규칙대로 **셀을 케이블타이로 고정**할 것. 주행 진동으로 셀이 튀어나오면
  순간 전원 차단 → MCU 리셋 → 원인 못 찾고 하루 날림.
- 극성 표기(+/−)를 트레이 바닥에서 확인하고 넣을 것. 거꾸로 넣으면 보호회로가 막아주지만
  믿을 건 아니다.

**충전기 (메가캐논 M2 Plus, 2구)**
- 생김새: 검은 플라스틱 크래들, 슬롯 2개, 슬라이딩 접점, USB 입력, 슬롯별 표시등.
- 빨강=충전 중, 초록=완충 (모델별 상이 — 설명서 확인).

**취급 규칙 (PLAN.md와 동일, 재확인)**
- 주행 후 홀더에서 셀 분리
- 모터가 느려지면 즉시 충전 (과방전이 셀을 죽인다)
- 맨 셀을 열쇠/동전 등 금속과 함께 주머니·서랍에 두지 말 것 (외부 단락 → 발열/발화)
- 부풀거나 뜨거워지면 즉시 사용 중단

**전압 계통 정리 (W2 화요일 확정 대상)**
| 레일 | 공급원 | 소비처 |

| 7.4V | 18650 ×2 | L298N 모터 출력단 |

## 8. 브레드보드 실험세트 A (MB-102 + 전원모듈 + 점퍼 65pcs)

**생김새**: 흰색 830홀 브레드보드(가운데 홈, 양옆 빨강/파랑 줄 = 전원 레일),
파란 소형 PCB에 배럴잭+USB가 달린 **전원모듈**(브레드보드 양 끝 레일에 꽂히는 형태,
점퍼로 5V/3.3V/OFF 선택), 여러 색 단단한 U자 점퍼선 한 봉지.

**활용 포인트**
- MB-102 구조: 가운데 홈 기준 위아래로 5홀씩 세로 연결, 가장자리 레일은 가로로 연결.
  **레일이 중간에서 끊긴 보드가 흔하다** — 처음에 멀티미터로 도통 확인해두면 좋다.
- 전원모듈은 배럴잭 7~12V 입력 시 5V/3.3V를 만들어준다. 배터리를 여기 물릴 수도 있지만,
  전류가 크지 않으니 **모터 전원으로는 쓰지 말 것** (로직 전용).
- 단단한 U자 점퍼는 배선이 깔끔해서 디버깅이 쉽다. 신호선/전원선 색을 규칙화할 것
  (예: 빨강=VCC, 검정=GND, 노랑=SCL, 파랑=SDA). W2 삽질 시간이 눈에 띄게 줄어든다.

## 9. 점퍼케이블 F-M 40P + M-M 40P

**생김새**: 무지개색 리본으로 붙어 있는 40가닥. 손으로 찢어서 필요한 개수만 쓴다.
F-M = 한쪽 암/한쪽 수, M-M = 양쪽 수.

**끝단 짝 맞추기 규칙**: 수핀에는 암을, 암소켓에는 수를 꽂는다. 즉 **연결할 두 쪽의 성별을
보고 그 반대를 고르면 된다.**

| 연결 | 케이블 |
|---|---|
| 센서 모듈(수핀) → Nucleo(암헤더) | **F-M** (암쪽을 모듈 핀에, 수쪽을 Nucleo 헤더에) |
| 센서 모듈(수핀) → 브레드보드 | F-M (암쪽을 모듈에) |
| 브레드보드 → Nucleo 암헤더 | M-M |
| 브레드보드 내부 | M-M 또는 U자 점퍼 |

- **부족한 케이블은 없다.** 가진 F-M / M-M 조합으로 이 프로젝트의 모든 배선이 가능하다.
- 그럼에도 **브레드보드를 경유하는 배선을 기본 전제로 삼는다.** 직결이 불가능해서가 아니라
  아래 세 가지 때문:
  1. **GND 공통화** — 접지를 한 레일에 모아야 여러 장치를 붙일 때 꼬이지 않는다.
  2. **기계적 고정** — 모듈이 공중에 매달리면 진동이 그대로 IMU 노이즈가 된다 (§4 참고:
     학습 데이터의 축 방향이 흔들리면 모델이 무의미해진다).
  3. **재배치 용이** — W3에서 센서를 측정 대상에 옮겨 붙일 때 Nucleo 쪽 배선을 안 건드려도 된다.

> **정정 (2026-07-31)**: 이 표는 원래 "센서(수핀)↔Nucleo(암헤더) 직결에는 암-암(F-F)이
> 필요한데 주문 목록에 없다"고 적고 ⚠️를 달아두었으나 **틀린 내용이었다.** F-F는 양쪽이 다
> 암이라 Nucleo의 암헤더에 애초에 꽂히지 않는다. 수핀(센서)과 암소켓(Nucleo)을 잇는 올바른
> 케이블은 **F-M**이고 이미 갖고 있다. 누락 부품은 없다.

## 10. [보류] 검은 절연 테이프 (다이소) — 구매 취소

> 라인트레이싱 자체가 계획에서 빠졌으므로 **구매할 필요가 없어졌다.** 다이소 갈 일 하나 줄음.
> 아래는 로봇 사이드 프로젝트 재개 시 참고용으로 보존.

**생김새**: 폭 약 18~19mm 검은 비닐 테이프.
**용도**: 흰 바닥(장판, 하드보드지, 전지)에 붙여 **주행 트랙**을 만든다.

**활용 포인트**
- 폭이 센서 간격과 맞아야 한다. 3센서 배치 간격을 테이프 폭(≈19mm) 기준으로 잡을 것.
- 곡률 반경을 너무 작게 만들면 2WD 차동 조향으로 못 따라간다. 첫 트랙은 **완만한 타원**부터.
- 반사 없는 무광 검정이 좋다. 광택 테이프는 각도에 따라 IR을 반사해 센서를 속인다.
- 배경도 중요: 흰색/밝은 무광 바닥. 나무 바닥·회색 장판은 대비가 부족할 수 있다.

### 12.3 여기서 읽히는 것

- **W2에 모든 부품이 한꺼번에 투입된다.** 5주 중 부품 리스크가 W2에 100% 몰려 있고,
  W3~W4는 "W2에 만든 것이 계속 돌아가는지"에만 의존한다.
  → W2에서 배선을 임시로 꽂아두면 W4 측정 중에 접촉 불량으로 데이터가 오염된다.
    **W2 금요일에 배선을 확정하고 물리적으로 고정(납땜/케이블타이/글루건)할 것.**
- **GY-521 하나가 W3 전체를 좌우한다.** 이 센서가 W2 수요일에 안 잡히면 W3가 통째로 밀린다.
  → 부품 중 유일하게 **대체 불가**. 다른 건 컷하거나 우회할 수 있지만 IMU는 없으면 프로젝트 A가 없다.
- **HC-SR04는 처음부터 컷 후보다.** W2 목요일에 안 되면 미련 없이 뺀다.
  (분압 저항 미확보 문제도 여기 걸려 있음 → §11)
- **W4에는 새 부품이 없다.** W4는 순수 소프트웨어/측정 주간이므로,
  부품 문제로 W4가 밀리면 그건 W2의 부채가 늦게 청구된 것이다.
- **W5는 부품 무관.** mini-infer(프로젝트 B)는 PC에서만 돈다.
  즉 하드웨어가 아무리 망해도 W5 산출물 절반은 지킬 수 있다.
