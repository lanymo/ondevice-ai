## 0. 한눈에 보는 현재 구성

```
             [Nucleo-F411RE]
                  |  |
                  |  +-- I2C1 (PB8/PB9) ------ [GY-521/MPU6050]  (IMU → AI 입력)
                  |  +-- (조건부) 타이머 IC --- [HC-SR04]         (재실감지 시나리오 시)
                  |
                 USB(ST-LINK) → PC: 전원 + 플래싱 + UART printf
```

모터 전원 계통이 없어져 배선이 단순하다. 확정 핀은 [pinmap.md](pinmap.md)가 원본.

## 1. Nucleo-F411RE — 두뇌

**생김새**: 가로로 긴 하늘색(민트) PCB. 위쪽 1/3이 잘린 선(perforation)으로 구분되는데
그 부분이 **ST-LINK 디버거**(고정 부품, 잘라내지 말 것). 아래쪽이 실제 STM32F411RE.
양옆에 검은 암(female) 헤더 2열 + 안쪽에 Arduino Uno 호환 헤더.
파란 버튼(B1, 사용자), 검은 버튼(B2, RESET), LED 3개(LD1 통신/LD2 사용자/LD3 전원),
**Mini-B USB 커넥터** 1개.

**용도**: STM32F411RE = Cortex-M4F @ 최대 100MHz(이 프로젝트는 84MHz 구동), Flash 512KB,
SRAM 128KB, FPU 있음. FreeRTOS, 센서 폴링, int8 추론이 전부 여기서 돈다.

**활용 포인트**
- USB 하나로 **전원 + 플래싱 + 디버깅 + 가상 COM 포트(UART printf)** 전부 해결.
- 보드에서 나오는 GPIO는 **3.3V 로직**. 5V 신호를 직접 물리면 핀이 죽을 수 있다
  (HC-SR04 Echo가 대표적인 함정 → §3).
- DWT 사이클 카운터(핵심 계측기)가 Cortex-M4 코어에 내장 → 별도 부품 불필요.

## 2. GY-521 (MPU-6050) — 이 프로젝트 AI의 입력원

**생김새**: 손톱 두 개 크기의 파란(또는 보라) 소형 PCB. 가운데 4mm 각짜리 검은 QFN 칩,
가장자리에 8핀 헤더(VCC, GND, SCL, SDA, XDA, XCL, AD0, INT). 핀헤더 납땜 옵션으로 구매함.

**용도**: 3축 가속도계 + 3축 자이로스코프 (6축 IMU). I2C 통신.
**추론 모델의 유일한 입력 데이터가 여기서 나온다** — 부품 중 유일하게 대체 불가.

**활용 포인트**
- I2C 주소: `AD0` 핀이 GND면 `0x68`, VCC면 `0x69`. 모듈에 보통 풀다운이 있어 기본 0x68.
  (HAL은 7비트 주소를 `<< 1` 해서 넘겨야 함 — 실제로 겪은 첫 삽질 포인트,
  [qna-core.md](qna-core.md) Q9)
- `WHO_AM_I` 읽기가 브링업 첫 단계. GY-521에 6500/9250 다이가 든 경우도 있으나 우리가
  쓰는 레지스터는 동일 (qna-core.md Q10).
- 전원 투입 후 **슬립 모드로 시작** — 깨우지 않으면 데이터가 계속 0.
  "배선은 맞는데 값이 안 변한다"의 90%가 이것 (qna-core.md Q11).
- 모듈에 3.3V 레귤레이터와 I2C 풀업이 이미 올라간 버전이 많다(GY-521 계열).
- **장착 방향을 고정하고 문서화할 것.** 학습 데이터의 축 방향과 추론 시 축 방향이 다르면
  모델이 통째로 무의미해진다. 양면테이프+케이블타이로 단단히 고정.
- 100Hz 스트림이 W2 DoD이자 그대로 W3 데이터셋이 된다. (달성: 2026-08-02 실측 검증)

## 3. HC-SR04 초음파 센서 ×2 — 조건부 (시나리오 W3 확정)

**생김새**: 파란 PCB에 **은색 원통 두 개**(눈처럼 생긴 트랜스듀서), 뒷면 4핀:
VCC, Trig, Echo, GND.

**용도**: 거리 측정(약 2cm~4m). 재실/움직임 감지 시나리오를 고르면 core로 승격,
기본 시나리오(IMU 예지보전)면 스트레치 (PLAN.md §0).

**활용 포인트**
- 동작: Trig에 10µs HIGH 펄스 → 센서가 8회 버스트 송신 → Echo 핀이 왕복시간만큼 HIGH.
  그 HIGH 폭을 타이머 인풋캡처로 잰다 ([sensor-actuator-basics.md](sensor-actuator-basics.md) §4).
- ⚠️ **Echo 출력은 5V**다. 3.3V인 STM32 핀에 직결 금지 — 분압 저항(예: 1kΩ+2kΩ) 또는
  레벨 시프터 필요. **저항 미확보 상태** (§6, pinmap.md 미결 항목).
- 측정 주기는 60ms 이상. 너무 빨리 쏘면 이전 반향이 섞여 값이 튄다.
- 부드러운 천/비스듬한 면은 반사가 안 돌아온다. 중앙값 필터 권장.

## 4. 브레드보드 실험세트 A (MB-102 + 전원모듈 + 점퍼 65pcs)

**생김새**: 흰색 830홀 브레드보드(가운데 홈, 양옆 빨강/파랑 줄 = 전원 레일),
배럴잭+USB가 달린 파란 **전원모듈**(양 끝 레일에 꽂힘, 점퍼로 5V/3.3V/OFF 선택),
여러 색 단단한 U자 점퍼선 한 봉지.

**활용 포인트**
- MB-102 구조: 가운데 홈 기준 5홀씩 세로 연결, 가장자리 레일은 가로 연결.
  **레일이 중간에서 끊긴 보드가 흔하다** — 멀티미터로 도통 확인해두면 좋다.
- 전원모듈은 HC-SR04 채택 시 5V 공급 후보 (Nucleo 5V 핀으로 충분하면 불필요).
- 배선 색 규칙은 [pinmap.md](pinmap.md)를 따른다.

## 5. 점퍼케이블 F-M 40P + M-M 40P

**생김새**: 무지개색 리본 40가닥, 찢어서 사용. F-M = 한쪽 암/한쪽 수, M-M = 양쪽 수.

**끝단 짝 맞추기**: 수핀에는 암을, 암소켓에는 수를 — 연결할 두 쪽의 성별 반대를 고른다.

| 연결 | 케이블 |
|---|---|
| 센서 모듈(수핀) → Nucleo(암헤더) | **F-M** |
| 센서 모듈(수핀) → 브레드보드 | F-M (암쪽을 모듈에) |
| 브레드보드 → Nucleo 암헤더 | M-M |
| 브레드보드 내부 | M-M 또는 U자 점퍼 |

- **부족한 케이블은 없다.** F-M / M-M 조합으로 모든 배선이 가능.
- 그래도 **브레드보드 경유를 기본 전제**로: ① GND 공통화가 깔끔하고 ② 모듈이 공중에
  매달리면 진동이 IMU 노이즈가 되며 ③ W3에서 센서를 측정 대상에 옮길 때 Nucleo 쪽
  배선을 안 건드려도 된다.

> **정정 (2026-07-31)**: 원래 "센서↔Nucleo 직결에는 F-F가 필요한데 없다"고 적었으나
> **틀린 내용이었다.** F-F는 Nucleo 암헤더에 애초에 꽂히지 않는다. 올바른 케이블은
> F-M이고 이미 있다. 누락 부품 없음.
