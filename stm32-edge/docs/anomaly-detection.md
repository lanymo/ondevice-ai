# 이상탐지(오토인코더) — 예지보전 시나리오용

> 학습 자료(축 B · 시나리오 의존). **삼성 축의 기본 시나리오 = 가전 예지보전**일 때 필요.
> 재실감지(분류) 시나리오를 고르면 이 문서 대신 일반 분류로 간다. 선행: [quantization-basics.md](quantization-basics.md),
> [timeseries-windowing.md](timeseries-windowing.md).

---

## 1. 문제의 성격 — "정상만 있고 고장은 거의 없다"

예지보전의 본질적 어려움: **정상 진동 데이터는 많은데 고장 데이터는 거의 못 모은다**(고장을
일부러 내기 어렵고 위험). 그래서 "정상 vs 고장"을 지도학습으로 분류하기 어렵다.

→ 발상 전환: **정상만 학습**하고, 들어온 신호가 "학습한 정상과 얼마나 다른가"로 이상을 잡는다.
이게 **비지도 이상탐지(unsupervised anomaly detection)**다.

> CS 연결: 지도 vs 비지도 학습의 구도. 여기선 라벨(고장) 없이 정상의 분포만 모델링.

---

## 2. 오토인코더 — 재구성 오차로 이상을 본다

- **구조**: 입력 → (인코더) → 작은 잠재벡터 z → (디코더) → 입력 복원. 병목(z)을 좁게 둬서
  **정상 패턴의 핵심만 압축**하도록 학습.
- **학습**: 정상 윈도우만으로 "입력 ≈ 출력"이 되게(재구성 손실 MSE 최소화) 훈련.
- **탐지**: 추론 시 **재구성 오차 = ‖입력 − 출력‖**. 정상은 잘 복원돼 오차가 작고, 못 보던
  이상 진동은 복원이 안 돼 **오차가 크다** → 임계값 넘으면 "이상".

```
정상 입력  → AE → 거의 같은 출력   → 오차 작음  → 정상
이상 입력  → AE → 뭉개진 출력      → 오차 큼    → 알림!
```

---

## 3. 임계값(threshold) 정하기 — 사실상 여기가 전부

- 정상 검증셋의 재구성 오차 분포를 구하고, 그 **상위 퍼센타일(예 p99)**을 임계값으로.
- 너무 낮으면 오탐(정상을 이상이라)↑, 너무 높으면 미탐(이상을 놓침)↑. **정밀도-재현율 트레이드오프.**
- 데모에선 손으로 "이상 진동"(툭툭 치기/불균형)을 흉내내 임계값이 실제로 반응하는지 확인
  (proxy 데이터임을 명시).

---

## 4. 더 단순한 대안 (모델이 과할 때)

측정이 목적이므로 오토인코더가 무거우면 더 가벼운 것부터:

- **통계적 임계값**: 윈도우 RMS/분산이 정상 범위를 벗어나면 이상. 가장 쌈.
- **마할라노비스 거리**: 정상 특징의 평균·공분산에서 얼마나 먼가(다변량 정규 가정).
- **One-class SVM** 등: PC 학습엔 되지만 MCU 추론은 무거울 수 있음.
- 권장: **통계적 베이스라인 → 오토인코더** 순으로 올려 "왜 굳이 AE인가"를 수치로 정당화.

---

## 5. int8로 MCU에 올리기

- 오토인코더도 dense/conv의 조합이라 [quantization-basics.md](quantization-basics.md)가 그대로 적용.
- 온디바이스에선 **디코더까지 돌려 재구성 오차만 계산**하면 됨(출력을 사람에게 줄 필요 없음).
- 재구성 오차 임계 비교는 정수 영역에서 처리 가능(스케일 주의).

---

## 6. 평가 — 고장 데이터가 적어도 하는 법

- 소수의 흉내낸 이상 샘플 + 정상으로 **정밀도/재현율**, 가능하면 임계값을 쓸어가며 ROC/PR 곡선.
- "정상 N개 중 오탐 M개, 흉내낸 이상 K개 중 탐지 J개" 같은 정직한 수치. proxy임을 명시.
